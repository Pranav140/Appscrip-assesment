# System Reliability & Failure Matrix

## "What Happens When X Fails?"

| Scenario | System Behavior | Guarantee | Verification / Testing | Residual Risk |
|---|---|---|---|---|
| **Same event delivered twice** | The second insert hits `UNIQUE (device_id, event_id)` on the `events` table; DB ignores insert and API responds `status: "duplicate"`. | At-least-once transport, exactly-once stored record. | Scenario `duplicates` in simulator; integration test in `packages/db`. | Low; requires client to provide RFC4122 or monotonic IDs. |
| **Accepted by API, but worker crashes** | Event was committed to `events` table with `status='pending'` or `status='processing'` with `locked_until`. When the lease expires, any active worker re-claims the row. | Zero event loss; durable queue. | Scenario `burst` followed by `docker compose kill -s KILL worker`. | Minor delay in processing equal to the unexpired lease duration (max 30s). |
| **Crash mid-incident creation** | Incident upsert, notification enqueue, and event mark-done execute in **one single database transaction**. A crash rolls back the whole unit. | Atomic effects; no orphan notifications or premature 'done' markers. | Transaction tests in Vitest suite. | None (Postgres WAL guarantees ACID). |
| **Notification webhook service down** | Notifications accumulate in the outbox table as `failed`. Worker retries with exponential backoff and jitter. Circuit breaker trips after 5 failures to avoid burning resources. Dead-letters after 8 attempts. | Incident creation is completely decoupled from external webhook uptime; zero lost alerts. | Simulator `scenario chaos` with webhook sink toggled `/admin/down`. | Webhooks delayed until receiver recovers or operator triggers manual retry. |
| **Device offline for minutes then replays** | Silence detector opens an incident. When network is restored, device replays buffered events. Server updates `last_seen_at` and auto-resolves the silence incident. | Safe reconnect burst; accurate device status tracking. | Scenario `offline-reconnect` in simulator CLI. | Temporary queue lag spike during mass reconnection; smoothed by batching. |
| **Ingest exceeds database capacity** | Ingest API queries queue depth. If pending count > 5,000, returns `429 Too Many Requests` + `Retry-After: 5`. | System does not OOM or crash; honest backpressure. | Scenario `burst` with 50k events. | Devices must possess durable local storage. |
| **Database fails / restarts** | API fails `/readyz` health check and rejects incoming traffic with 503. Devices retain un-acked events in local disk buffer and retry. | Durability is anchored at the devices until Postgres acks commit. | Stopping Postgres docker container mid-stream. | Temporary fleet-wide ingestion halt. |
| **Browser loses connection to SSE stream** | Browser detects disconnect or offline event. Persistent top banner alerts operator with timestamp of last known state. On reconnect, `Last-Event-ID` cursor replays missed items or triggers REST cache invalidation. | No duplicate rows in UI; smooth catch-up without page reload. | Disconnecting network in browser DevTools or killing API container. | Momentary stale view while network is broken. |
